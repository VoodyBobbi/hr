# HR-бот ПОЛАТИ

Чат-бот для найма рабочих на вахту. Отвечает кандидатам на вопросы о работе
и собирает с них анкету из 29 пунктов. Работает сразу в двух местах — на
сайте и в Telegram — на одном и том же коде. Заполненная анкета приходит в
Telegram-группу отдела подбора.

## Запуск

Нужен Python 3.11 или новее.

```powershell
cd "путь\к\папке\HR"
python -m venv venv
.\venv\Scripts\activate
python start.py
```

Первая команда переходит в папку проекта. Вторая создаёт отдельное место для
библиотек, чтобы они не мешались с остальными программами на компьютере.
Третья это место включает — слева в строке появится `(venv)`. Четвёртая
запускает всё остальное: ставит библиотеки, ставит сертификат Минцифры
(без него GigaChat не отвечает), пересобирает поиск, если данные менялись, и
поднимает сайт вместе с Telegram-ботом.

Когда запустилось — открыть **http://localhost:8000**. Остановить — `Ctrl+C`
в том же окне.

**Как понять, что всё получилось.** Ищи в консоли строку:

```
Uvicorn running on http://0.0.0.0:8000
```

Есть она — сайт работает. Нет её — сайта нет, что бы ни печаталось выше.
Строка «Запущено: сайт и Telegram-бот» сообщает только о попытке запуска, а
не о её успехе, на неё ориентироваться нельзя.

На Linux и macOS третья команда другая: `source venv/bin/activate`.

Модель, которая ищет по смыслу (файл на 470 МБ), грузится не при запуске, а
при первом вопросе кандидата. По журналу это занимает 8,5–11 секунд. Сайт в
это время уже открывается и отвечает.

## Что вписать перед первым запуском

Один раз. В файле `.env` в корне проекта вписать ключ GigaChat:

```
GIGACHAT_CREDENTIALS=ключ_из_личного_кабинета_Сбера
```

Файла `.env` нет — он создастся сам при первом `python start.py`, тогда
впиши ключ и запусти заново.

### Сохранить ключ шифрования

При каждом запуске в консоль печатается такая строка:

```
ENCRYPTION_KEY=N-OwSqWBRNsyloq5LI6...
```

**Скопируй её в менеджер паролей или в заметку.** Этим ключом зашифрованы
анкеты кандидатов и тексты в журнале. Пропадёт файл `.env`, а копии ключа не
будет — прочитать анкеты не сможет никто, включая тебя.

## Как бот отвечает

Три пути, от самого дешёвого к самому дорогому.

**1. Готовый ответ.** Если вопрос похож на один из 69 записанных в
`data/faqs.json` — ответ берётся оттуда и уходит кандидату дословно.
Нейросеть не вызывается вообще, ответ мгновенный и бесплатный. Насколько
точно вопрос должен совпасть — настройка `FAQ_MIN_SIMILARITY`, сейчас 0.62.

**2. Через GigaChat.** Готового ответа не нашлось. Тогда поиск выбирает из
`data/kb/` до 5 фактов, подходящих к вопросу, и отдаёт нейросети только их —
не всю базу. Нейросеть пересказывает их своими словами. Ограничения: фактов
не больше 2500 символов, из разговора передаются последние 20 сообщений,
ждать ответа не дольше 30 секунд.

**3. Анкета.** Кандидат согласился оставить заявку — включается опрос из 29
вопросов. Нейросети здесь нет совсем: вопросы написаны заранее, ответы
проверяет код, а на каком шаге стоит разговор, записано в карточке
кандидата.

Такое разделение экономит деньги: за нейросеть платят по объёму текста, а
большинство вопросов кандидатов повторяются и до неё не доходят.

**Паспортные данные в нейросеть не попадают.** Ответы кандидата на шаги
анкеты — паспорт, СНИЛС, ИНН, адреса — помечаются в истории разговора и
выбрасываются перед отправкой в GigaChat. Это проверяется автоматически,
тест `tests/test_utechka.py`.

## Как менять то, что говорит бот

### Добавить готовый ответ

Открыть `data/faqs.json`. Внутри обычный список, допиши в него блок:

```json
{
  "question": "Есть ли на объекте интернет?",
  "keywords": "интернет вайфай связь мобильный",
  "answer": "На большинстве объектов есть мобильная связь и интернет."
}
```

`keywords` — одна строка со словами, которыми кандидат может спросить то же
самое. Чем их больше, тем лучше бот узнаёт вопрос.

Этот ответ уйдёт кандидату **дословно**, нейросеть его не тронет. Поэтому
пиши так, как хочешь, чтобы прочитал человек.

### Добавить факт для нейросети

Открыть подходящий файл в `data/kb/`. Внимание: внутри не список, а тема со
списком записей внутри `entries` — добавлять надо туда:

```json
{
  "topic": "Условия труда",
  "entries": [
    {
      "id": "cond.internet",
      "title": "Интернет и связь на объекте",
      "keywords": ["интернет", "вайфай", "связь"],
      "text": "На большинстве объектов есть мобильная связь..."
    }
  ]
}
```

Здесь `keywords` — список в квадратных скобках, а не строка, как в
`faqs.json`. Такой факт нейросеть перескажет своими словами.

### Поменять характер бота

`data/system_prompt.md` — правила: как разговаривать, что запрещено, какой
длины отвечать. Фактов и цифр о компании там нет и быть не должно, они в
`data/kb/`. Иначе нейросеть начнёт брать цифры из правил, а не из базы.

### После правок

`Ctrl+C`, потом `python start.py`. Программа сверит данные с прошлым разом и
пересоберёт поиск, только если что-то менялось. Правки в
`system_prompt.md` подхватываются сразу, без перезапуска.

## Telegram

### Бот для кандидатов

1. Написать [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Полученный токен вписать в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=1234567890:AAA...
   ```
3. Перезапустить проект.

Бот отвечает только в личных сообщениях. В группах молчит — в коде стоит
фильтр `ChatType.PRIVATE`. Сделано специально, чтобы бота можно было держать
в рабочей группе, и он не влезал в разговоры HR.

### Уведомления отделу подбора

Кандидат дозаполнил анкету — в рабочую группу приходит сообщение:

```
Новая заявка от кандидата
ФИО: Иванов Иван Иванович
Вакансия: Монтажник

[ Показать все данные кандидата ]
```

Паспорт, СНИЛС и ИНН в самом сообщении **не показываются** — оно висит в
ленте, и его видит каждый, кто пролистывает переписку. Полная карточка
приходит по кнопке, отдельным сообщением.

Группа задаётся в `.env`:

```
TELEGRAM_HR_GROUP_CHAT_ID=-3869481165
```

Бота надо добавить в группу участником, иначе он не сможет туда писать.
Если уведомления не приходят, попробовать тот же номер с `-100` в начале:
`-1003869481165`. У обычных групп номер без этой приставки, у супергрупп — с
ней, а группа становится супергруппой сама.

## Как посмотреть всех кандидатов

Анкеты лежат в `candidates/candidates.csv` и зашифрованы целиком. Excel этот
файл не откроет — там нечитаемая мешанина. Так сделано специально: если файл
куда-то утечёт, прочитать его без ключа нельзя.

**Единственный способ увидеть всех кандидатов — выполнить команду:**

```powershell
python -m scripts.export_candidates
```

После неё в папке `candidates` появляется файл `candidates_readable.csv` —
те же анкеты, но расшифрованные. Его открывают в Excel: строки — 29 полей,
колонки — кандидаты. Команда сама напишет, сколько кандидатов выгрузила.

Открыть, не выходя из терминала:

```powershell
Invoke-Item candidates\candidates_readable.csv
```

**Этот файл не зашифрован, в нём паспорта и СНИЛС открытым текстом.** Сам он
не создаётся и в git не попадает. Посмотрел — удали:

```powershell
Remove-Item candidates\candidates_readable.csv
```

Зашифрованный `candidates.csv` при этом останется на месте, данные никуда не
денутся.

### Удалить данные кандидата

По требованию кандидата, как велит 152-ФЗ:

```powershell
python -m scripts.delete_candidate 7
```

`7` — номер колонки этого кандидата в выгруженной таблице. Удалится всё:
карточка, переписка и строки в журнале.

Кандидат может удалить свои данные и сам — написать боту «удали мои данные».
Бот переспросит и удалит.

## Журнал

Всё пишется в **один файл** — `logs/logs.csv`: и разговоры с кандидатами, и
системные события. Открывается Excel'ем. Тринадцать колонок:

| Колонка | Что в ней |
|---|---|
| Дата и время | когда записана строка |
| Событие | что это за строка, значения ниже |
| Источник | `site` или `telegram` |
| ID пользователя | кто писал: сессия на сайте или номер в Telegram |
| Вопрос | текст кандидата, **зашифрован** |
| Ответ | текст бота, **зашифрован** |
| Время ответа (мс) | сколько заняло, в миллисекундах |
| Статус | `ok`, `внимание` или `ошибка` |
| Комментарий | пояснение к системному событию |
| Токены на вход | сколько текста ушло в нейросеть |
| Токены на выход | сколько она вернула |
| Всего токенов | сумма двух предыдущих |
| Кешировано токенов | сколько она не посчитала повторно |

**Четыре последние колонки — это и есть расход на нейросеть.** Пустые
значения означают, что нейросеть не вызывалась: сработал готовый ответ или
шёл шаг анкеты. Чем больше пустых строк, тем дешевле. Посчитать итог за всё
время:

```powershell
python -m scripts.token_report
```

Что бывает в колонке «Событие»:

| Событие | Что значит |
|---|---|
| `dialog` | сообщение кандидата и ответ бота |
| `start` | проект запущен |
| `model` | загрузилась модель поиска, время — в «Время ответа» |
| `index` | пересобран поиск |
| `gigachat` | сбой обращения к нейросети |
| `notify` | уведомление в группу HR: ушло или нет |
| `delete` | удалены данные кандидата, след для 152-ФЗ |
| `block` | кого-то заблокировало за спам |
| `marker` | отклонена попытка навязать анкету |

Зашифрованы только «Вопрос» и «Ответ» — единственные колонки, где может
оказаться личный текст. Остальное открыто намеренно: так видно состояние
системы, не имея ключа шифрования.

Строки старше 90 дней удаляются сами. Срок меняется настройкой
`LOGS_RETENTION_DAYS`, значение `0` означает «хранить вечно».

## Настройки в файле .env

Первые пять нужны для работы, остальные можно не трогать.

| Настройка | Сейчас | Что делает |
|---|---|---|
| `GIGACHAT_CREDENTIALS` | — | ключ из личного кабинета Сбера, обязательно |
| `ENCRYPTION_KEY` | создаётся сам | ключ, которым шифруются анкеты |
| `ALLOWED_ORIGINS` | `http://localhost:8000` | с какого адреса открывается сайт |
| `TELEGRAM_BOT_TOKEN` | — | токен бота от @BotFather |
| `TELEGRAM_HR_GROUP_CHAT_ID` | — | номер группы, куда идут заявки |
| `FAQ_MIN_SIMILARITY` | 0.62 | насколько точно вопрос должен совпасть с готовым ответом |
| `KB_MIN_SIMILARITY` | 0.35 | то же для фактов, уходящих нейросети |
| `KB_TOP_K` | 5 | сколько фактов отдавать нейросети за раз |
| `KB_CONTEXT_CHAR_LIMIT` | 2500 | предел объёма этих фактов, в символах |
| `GIGACHAT_TIMEOUT_SECONDS` | 30 | сколько ждать ответа нейросети |
| `CHAT_RATE_LIMIT_PER_MINUTE` | 20 | сколько сообщений в минуту пускать с одного адреса |
| `LOGS_RETENTION_DAYS` | 90 | сколько дней хранить строки журнала |

## Если что-то не работает

**В консоли `CERTIFICATE_VERIFY_FAILED`**

Не установлен сертификат Минцифры, без него GigaChat не отвечает. Ставит
`python start.py` сам, качает его с `gu-st.ru`. Не помогло — проверить, что
этот адрес не заблокирован.

**Бот пишет «Пока не могу сформулировать точный ответ»**

Либо нет связи с GigaChat — смотри консоль, либо в `.env` не вписан
`GIGACHAT_CREDENTIALS`.

**Бот забывает разговор после каждого сообщения**

Проверить `ALLOWED_ORIGINS` в `.env`: по нему программа понимает, локальный
это запуск или сетевой, и настраивает cookie. Для проверки на своём
компьютере там должно быть `http://localhost:8000`. При запуске печатается
строка `[app] Cookie сессии: ...` — по ней видно, что определилось.
Переписка на сайте привязана к cookie браузера и живёт 30 дней.

**«Вы отправляете сообщения слишком часто», хотя писали медленно**

Защита от спама. Срабатывает на повторяющихся одинаковых сообщениях.
Блокировка на 2 минуты, снимается сама. Во время заполнения анкеты защита
выключена, чтобы человека не заблокировало на середине. Настройки — вверху
`backend/rate_limiting.py`.

**Поиск находит не то**

Крутить пороги в `.env`. `FAQ_MIN_SIMILARITY` (сейчас 0.62): бот отвечает не
по делу — поднять до 0.70; часто «не знает» того, что в базе есть — опустить
до 0.55. `KB_MIN_SIMILARITY` (0.35) — то же для фактов, уходящих нейросети.

## Тесты

```powershell
python -m pytest
```

101 проверка в 57 функциях, проходят примерно за секунду. Ставить ничего не
нужно, всё установилось вместе с проектом.

Что проверяют: анкету и переходы между шагами, согласие по 152-ФЗ, удаление
данных, защиту от спама, форматы всех 29 полей, поиск (различает ли он
близкие вопросы — зарплата монтажника, альпиниста, изолировщика),
непопадание паспортных данных в нейросеть, журнал.

Запускать после любой правки в `backend/anketa.py`, `backend/assistant.py`
или `backend/validators.py`. Тесты работают на подставных данных во
временной папке — настоящие анкеты они не трогают.

Если меняли модель поиска — поднять `EMBEDDING_VERSION` в
`backend/build_index.py`, иначе поиск не пересоберётся и сломается молча.

## Docker

```bash
docker compose up --build
```

Поднимет сайт на http://localhost:8000. Файл `.env` нужен тот же.
Контейнер перезапускается сам, если упадёт. Для сервера — вписать свой домен
в `ALLOWED_ORIGINS` и поставить перед контейнером обратный прокси с HTTPS.
