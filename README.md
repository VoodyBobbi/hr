# HR-ассистент ООО ПОЛАТИ


Вопросно-ответный AI-ассистент киборг (HR-менеджер по подбору персонала) для строительной компании
ПОЛАТИ. Отвечает кандидатам на вопросы по вакансиям и условиям работы строго на основе базы
знаний компании, помнит контекст диалога и помогает заполнить анкету кандидата.

Пайплайн: **данные (FAQ + база знаний) → RAG через FAISS → backend на FastAPI + GigaChat →
чат-виджет на сайте и Telegram-бот**.

За счёт супер автоматизации ответов на любые вопросы кандидатов ассистент снимает до 70–80% нагрузки
с рекрутёров и сокращает среднее время первого ответа кандидату, работая 24/7 без участия
человека.

## Возможности

- **Ответы только по базе знаний компании** — модель ограничена данными из `data/`, не выдумывает
  факты (RAG-подход), и не отвечает на вопросы не по теме трудоустройства (см. `system_prompt.md`).
- **Память диалога** — история переписки хранится по каждому пользователю, общение остаётся
  осмысленным.
- **Два канала** — чат-виджет на сайте и Telegram-бот, общая логика ответа.
- **Заполнение анкеты кандидата** — ассистент по одному полю собирает данные (с проверкой формата
  каждого поля) и сохраняет карточку через служебные маркеры в ответе модели.
- **Персональные данные — отдельно от кода и зашифрованы.** Анкеты, история переписки и логи
  хранятся вне репозитория, на диске администратора (по умолчанию `~/hr-data`, см. раздел
  «Переменные окружения»). Файл анкет (`candidates.csv`) зашифрован (Fernet), ключ — отдельно,
  в переменной окружения `ENCRYPTION_KEY`.
- **Удаление данных кандидата по запросу** — `python -m scripts.delete_candidate <ID>` стирает
  анкету, привязку сессии и историю переписки конкретного кандидата.
- **Логирование** — все обращения пишутся в `logs/logs.csv` (источник, вопрос, ответ, время
  ответа, статус). Логи и история переписки хранятся полностью, без ограничения срока.
- **Горячая перезагрузка** — при изменении промпта, базы знаний или индекса они подхватываются на
  лету без перезапуска сервера.

## Структура проекта

```
HR/
├── backend/
│   ├── app.py            # FastAPI-приложение: отдаёт сайт, маршруты /chat и /health
│   ├── assistant.py      # ядро: RAG-поиск, сборка промпта, вызов GigaChat, память, маркеры
│   ├── build_index.py    # сборка FAISS-индекса из data/faqs.json (эмбеддинги)
│   ├── rag_index.py      # загрузка индекса и поиск ближайших векторов (FAISS)
│   ├── candidates.py     # карточки кандидатов: чтение/запись, валидация, удаление
│   ├── validators.py     # проверка формата полей анкеты (телефон, паспорт, СНИЛС, ИНН и т.д.)
│   ├── crypto_utils.py   # шифрование/расшифровка candidates.csv (Fernet)
│   ├── paths.py          # где на диске лежат анкеты/история/логи (см. HR_DATA_DIR ниже)
│   ├── telegram_bot.py   # Telegram-бот на том же ядре ассистента
│   └── logger.py         # запись обращений в logs.csv
├── scripts/
│   └── delete_candidate.py   # удаление всех данных кандидата по его ID (152-ФЗ)
├── data/
│   ├── faqs.json             # пары «вопрос — ответ» (источник для векторного индекса)
│   ├── knowledge_base.json   # структурированная база знаний компании (в системном промпте)
│   ├── system_prompt.md      # системный промпт (роль и правила ассистента)
│   ├── faiss_index.bin       # готовый FAISS-индекс (создаётся build_index.py)
│   ├── faqs_metadata.npy      # метаданные векторов (вопрос/ответ)
│   └── faqs_hash.txt         # хэш faqs.json для пропуска лишней пересборки индекса
├── frontend/
│   ├── index.html        # страница сайта с чат-виджетом в правом нижнем углу
│   └── background.png     # фон страницы
├── run_all.py            # запуск сайта и Telegram-бота одной командой
├── docker-compose.yml    # локальный запуск в Docker с данными на этом компьютере
├── .env.example          # шаблон .env — какие переменные нужны
└── requirements.txt      # зависимости Python
```

Анкеты кандидатов, история переписки и логи **больше не хранятся внутри репозитория** — папок
`candidats/` и `logs/` в коде больше нет, они создаются приложением на диске администратора (по
умолчанию `~/hr-data`, см. «Переменные окружения»). Это отдельно от кода намеренно: раньше
`candidats/candidates.csv` через `git add .` случайно попал в git и в публичный GitHub-репозиторий.

## Как это работает

1. **Данные.** Частые вопросы лежат в `data/faqs.json` в формате `{"question": ..., "answer": ...}`.
   Развёрнутая структурированная информация о компании, вакансиях и условиях — в
   `data/knowledge_base.json`. Поведение ассистента задаётся в `data/system_prompt.md`.
2. **Индекс.** `build_index.py` превращает каждую пару «вопрос — ответ» в вектор моделью
   `paraphrase-multilingual-MiniLM-L12-v2` (sentence-transformers) и сохраняет FAISS-индекс
   (`faiss_index.bin`) вместе с метаданными (`faqs_metadata.npy`).
3. **Запрос.** При сообщении пользователя `assistant.py` векторизует вопрос, ищет в FAISS похожие
   FAQ, добавляет их и полную базу знаний в контекст, подмешивает историю диалога и системный
   промпт, после чего вызывает **GigaChat**.
4. **Анкета.** Модель может дописывать в конец ответа служебные маркеры
   (`###SAVE_FIELD:поле=значение###`, `###LAW_ACK###`, `###CARD_CONFIRMED###`) — они вырезаются из
   ответа пользователю и сохраняют данные в карточку кандидата.
5. **Интерфейс.** `app.py` отдаёт сайт (`frontend/index.html`) и принимает запросы на `POST /chat`;
   `telegram_bot.py` использует то же ядро для Telegram.

## Требования

- Python 3.10+ (рекомендуется 3.11) — или Docker/Docker Compose, если запускаете в контейнере
- Доступ к GigaChat API (переменная `GIGACHAT_CREDENTIALS`)
- Токен Telegram-бота — только если нужен Telegram-канал (`TELEGRAM_BOT_TOKEN`)

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

```env
GIGACHAT_CREDENTIALS=ваш_ключ_авторизации_GigaChat
TELEGRAM_BOT_TOKEN=токен_вашего_бота   # опционально, только для Telegram

# Обязательно — ключ шифрования candidates.csv. Сгенерировать:
#   python -m backend.crypto_utils
ENCRYPTION_KEY=

# Опционально — где на диске хранить анкеты/историю/логи.
# По умолчанию: ~/hr-data (домашняя папка текущего пользователя).
# HR_DATA_DIR=/home/admin/hr-data
```

Файл `.env` не коммитится (см. `.gitignore`). `ENCRYPTION_KEY` — потеря этого значения означает
потерю доступа к данным в `candidates.csv`, храните его отдельно (например, в менеджере паролей).

## Установка и запуск

Приложение рассчитано на локальный запуск — на компьютере/сервере администратора, без облачного
хостинга. Персональные данные остаются на этой же машине (см. «Переменные окружения» выше).

```bash
# 1. Клонировать репозиторий и перейти в него
git clone https://github.com/VoodyBobbi/HR.git
cd HR

# 2. Создать и активировать виртуальное окружение
python3 -m venv venv
source venv/bin/activate        # Linux/macOS
# .\venv\Scripts\activate       # Windows

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Скопировать .env.example в .env и заполнить GIGACHAT_CREDENTIALS

# 5. Сгенерировать ключ шифрования анкет и добавить его в .env
python -m backend.crypto_utils

# 6. Собрать векторный индекс из data/faqs.json
python -m backend.build_index
# принудительная пересборка: python -m backend.build_index --force

# 7. Запустить сайт (FastAPI + чат-виджет)
uvicorn backend.app:app --host 0.0.0.0 --port 8000
```

Откройте <http://localhost:8000> — в правом нижнем углу появится иконка чата. Анкеты, история и
логи появятся в `~/hr-data` (или в папке из `HR_DATA_DIR`, если задали свою).

### Запуск в Docker (тот же локальный компьютер)

```bash
docker compose up --build
```

Поднимет сайт на <http://localhost:8000>; данные будут лежать в папке `./hr-data` рядом с
`docker-compose.yml` (путь настраивается в самом файле). `.env` должен быть заполнен заранее —
Compose передаёт его в контейнер автоматически.

### Запуск сайта и Telegram-бота вместе

```bash
python run_all.py
```

Поднимет сайт на `http://localhost:8000` и Telegram-бота (нужен `TELEGRAM_BOT_TOKEN`).
Остановить всё — `Ctrl+C`.

## API

| Метод | Путь      | Описание                                                        |
|-------|-----------|----------------------------------------------------------------|
| GET   | `/`       | Главная страница сайта с чат-виджетом                           |
| POST  | `/chat`   | Отправить сообщение ассистенту                                   |
| GET   | `/health` | Проверка работоспособности сервиса (`{"status": "ok"}`)         |

Пример запроса к `/chat`:

```json
{
  "message": "Какие у вас есть вакансии?",
  "top_k": 3,
  "session_id": "необязательный-идентификатор-диалога"
}
```

Ответ:

```json
{
  "answer": "...",
  "context": [ ... ],
  "session_id": "..."
}
```

Если `session_id` не передан, он генерируется автоматически и возвращается в ответе — используйте
его в следующих запросах, чтобы сохранялась память диалога.

## Удаление данных кандидата (152-ФЗ)

По запросу кандидата на удаление его персональных данных:

```bash
python -m scripts.delete_candidate <ID_кандидата>
```

ID — это номер колонки в `candidates.csv` (см. поле «ID кандидата» в карточке), не телефон и не
ФИО. Скрипт спросит подтверждение и удалит: строку кандидата из `candidates.csv`, привязку его
сессии в `candidate_sessions.json` и файл(ы) истории переписки. `logs/logs.csv` не затрагивается
— решение: логи хранить полностью, без исключений.

## Обновление базы знаний

- Изменили `data/faqs.json` — пересоберите индекс: `python -m backend.build_index`.
- Изменили `data/knowledge_base.json` или `data/system_prompt.md` — пересборка не нужна, они
  подхватываются на лету при следующем запросе.

## Постоянная работа на компьютере администратора

Проект больше не рассчитан на облачный хостинг (Render и т.п.) — он работает локально, на
компьютере или сервере, который контролирует администратор, а персональные данные остаются на
этой же машине. Чтобы сайт не отключался при закрытии терминала и поднимался заново после
перезагрузки компьютера, выберите один из вариантов:

- **Docker Compose** (проще всего) — `docker compose up -d --build`. В `docker-compose.yml` уже
  указано `restart: unless-stopped` — контейнер перезапустится сам после перезагрузки машины,
  пока Docker сам настроен на автозапуск.
- **systemd** (Linux, без Docker) — создайте юнит, который выполняет
  `uvicorn backend.app:app --host 0.0.0.0 --port 8000` из виртуального окружения проекта, и
  включите `systemctl enable`.
- **Планировщик заданий / NSSM** (Windows, без Docker) — запустите ту же команду uvicorn как
  задачу при входе в систему или как службу через NSSM.

Во всех трёх случаях `.env` должен быть на месте до запуска — без `GIGACHAT_CREDENTIALS` и
`ENCRYPTION_KEY` приложение не стартует.
